This bounded pass did not establish a call from the selected source evaluators to the primary mapped-data getter, or a primary-data binding into CPU transfer functions. The evaluators' superficially matching slot+0x18 calls consume environment metadata. The selected CPU CreateDSP method does not read the two supplied configuration-interface arguments. The CPU ABI closes another ambiguous edge. HrtfApo0x18000b9e0 supplies the global configuration andconfiguration+8 to the returned DSP factory. The actual CPU `HrtfDspCpuFlex2Factory` vtable0x180141248 has CreateDSP0x180004c30 atslot+0x18. At0x180004c30 it preserves R9D (source count). Before calling0x180005034 at0x180004c6a, it replaces RCX with an output-DSP pointer, RDX with a local block-size pointer(0x400), R8 with source-count pointer, and R9 with flag pointer(0). It never reads incoming RDX/R8. The output-interface pointer is subsequently taken from the caller's stack. Thus the primary/environment arguments supplied by the APO are unused by this particular CreateDSP method; missing decompiler arguments cannot be assumed to conceal their consumption.

0x180005034→0x180005458→0x180003d54 allocates a new HrtfDspEngine and owned source/parameter vectors, requiring block0x400 and flag0, then constructs its processing object through0x18000752c. The inspected allocation chain shows no primary pointer retention or primary-byte copy. It does not establish what a later CPU control/filter-bank operation or the processing object's own initialization may obtain elsewhere. This pass did not expand into those unrelated operations.

All edited Java/PowerShell helpers compiled and executed successfully. Both evidence files have complete selected function output and no decompile failure; assembly verifies interface assignments and the disputed ABI. A second pass checked primary-versus-environment vtables, source QueryInterface adjustment and incoming-register use. Original DLL hashes were rechecked. No live uptake or filter comparison was performed.

No such caller was found among0x18000d724,0x18000f098,0x180010544,0x180010854,0x18000f678 or the selected CPU CreateDSP chain. Until then, neither mapped aliasing, coefficient copying, automatic update uptake, nor permanent nonuse of primary data is established for the active renderer.
