# DTS object decoder source audit

Audited the local `harletty-bridge` checkout at tag `v0.9.0`, commit `9556bcedfd6e71461d49fd3f03fcfdf87351b67f`, on 2026-10-16. All source paths below are relative to `SonicRendererResearch/continuation/open_object_decoder/harletty-bridge/`. This worker read source, local documentation, the primary's header evidence and the official ETSI specification. No build, test executable, dependency download, media decode, REA operation or system change ran in this worker's audit. The checkout remained clean.

The repository contains a concrete legacy DTS:X extension-waveform and position interface usable by a custom panner. It is materially different from the vendor MFT's fixed speaker projection. Its implemented transport is DTS Coherent Acoustics core plus EXSS/XLL; this audit found no DTS-UHD top-level decoder. The primary's later compressed-header inspection identifies Kinsetsu as UHD-framed and channel-based, outside that front end. This conclusion uses compressed data and container signaling, not the Media Foundation subtype GUID or our vendor DLL's internal “Profile2” function name.

A minimal custom-renderer extraction sequence is: decode a legacy access unit, validate usable equal-length extension planes, detect presentation, parse metadata, build/resolve the fold plan, subtract each known folded contribution from the bed, and submit each known extension PCM plane with its fixed role or transmitted XYZ at the frame's accumulated sample index. The source supplies the necessary information for that sequence on its supported forms. Runtime correctness, object trajectory truth, finite handling and CPU tails still require tests; a source interface is not runtime proof.

## Algorithm limits and metadata timing

`MAX_SOURCES=9`, with eight reference-bed columns and sixteen fold-speaker slots (`dca/src/dcadec/xmeta.rs:37–48,130–155`). Standard `Height` is four fixed height feeds and no dynamic objects. Alternate presentations are one, two, four or five object-position feeds followed by four fixed heights; the D0 component form exposes three components at C/L/R for one underlying declared object, and `ObjectOnly` has one object with no height quartet. `XPresentation::is_experimental()` marks every non-standard-height form experimental (`dca/src/spatial.rs:60–92,144–181`). Feed count is not a universal authored-object capacity, and D0's component channels must not automatically be described as independent original stems.

Metadata recognition is deliberately narrow. `xmeta.rs:914–950` checks expected source count and supported reference layout. The type-241 parser (`1023–1195`) checks bounded declaration indices, known modes/options and position gain fields; unfamiliar flags/options fail instead of being skipped as if understood. `parse_type241_components` (`1210–1262`) handles another bounded form. The parser recovers one spherical state per object for each frame, not arbitrary intra-frame trajectories, authored names, object size/spread or a general scene graph. The bridge assigns IDs `10 + feed`, with names `X{feed}`; these are host-generated feed identities rather than proven original authored IDs (`dts_pipeline.rs:43–49,835–841,894–899`).

The realtime bridge emits interleaved i32 PCM ordered as active bed speakers, fixed extension feeds, then object feeds, with `RChannelLabel::Object` and `RObjectChannel {id, channel}` mappings (`dts_pipeline.rs:718–775`). The lower-level `HdFrame` float planes avoid that extra interleave/quantization stage if integrating directly. Its object `REvent`s include absolute accumulated `sample_pos`, Cartesian XYZ, `gain_db=0`, `size=[0;3]`, and `ramp_duration=0` (`820–878`). Events emit on a move, declaration change, or 2 Hz heartbeat, carrying all known objects together. The host sample position comes from accumulated decoded samples (`432–461`), not a container PTS supplied by this DTS front end. A custom player must preserve external timeline/discontinuity alignment itself.

The default bridge enables mode-0 render reconstruction and unknown-fold estimation (`dts_pipeline.rs:68–100,686–712`). If metadata parsing fails, it reuses the last readable metadata; without that, standard heights use a configurable fallback and other profiles begin with unknown folds (`592–613`). Only planes whose fold becomes known are emitted as nonzero extension signals (`720–732`); unknown feeds stay in the bed and are muted as separate outputs. This behavior avoids an automatic double render but can hold stale positions or use estimated/fallback coefficients. It must be surfaced in any validation result rather than reported as fully transmitted metadata.

The bridge allocates per-frame vectors for active channels, cleaned bed PCM, interleaved output, positions and events (`627–648,720–724,835–866`), despite the metadata reader itself using bounded allocation-free parsing. `FoldRenderer` allocates/rebuilds its hull when layout changes (`xrender.rs:338–342`). No sustained throughput, allocation count or callback deadline was measured in this audit.

Decode errors also affect timeline policy. Strict mode returns an error and requests pipeline reset; non-strict mode drops the frame and continues (`dts_pipeline.rs:541–564`). The decoded-sample counter advances in successful-frame branches (`461,491,516`), not in those decode-error branches. An integration that needs container-time conservation must account for dropped encoded durations explicitly rather than assuming these sample indices preserve gaps.

`harletty/src/dts_to_oamd.rs` is an export projection, not the PCM decoder. `DtsLayout::from_hd` resolves object feed positions and substitutes `[0,0,0]` when unavailable (`211–269`); conforming a bed may also create static objects from fixed speakers (`218–220,258–260`). `convert_dts` creates one object block at sample offset zero for the whole frame, with no ramp (`366–399`). OAMD conversion clamps coordinates and reverses the y convention (`340–346`). The offline handler timestamps these frame events using `decoded_samples` and writes only changed events (`harletty/src/cli/decode/dts_handler.rs:901–949`). For a custom panner, use raw spherical/ADM positions plus PCM/sample timing rather than treating every exported “object” as an independently authored moving object.

## Decisive next checks

Kinsetsu's observed UHD framing and channel-based flag resolve the immediate fixture mismatch. Keep the validated vendor PCM route separate from this legacy object alternative. After the primary reviews build/dependency scripts, the shipped core fixture can test decoder basics, and Kinsetsu can exercise the expected unsupported-input outcome. Actual object proof then requires a supported legacy object corpus with nonzero extension waveforms and independently known time-varying position reference, with skip counts explicitly recorded. Test waveform identity, cleaned-bed conservation, feed-to-position correspondence, sample alignment, metadata failures, presentation changes and CPU/allocation tails before using it as a live panner source. General DTS-UHD, arbitrary object counts, original authored IDs and intra-frame trajectories remain unimplemented or unverified in this source, not demonstrated impossible in DTS as a whole.

Second pass cross-checked public reexports against definitions, bridge event/channel indices against PCM write order, fallback/estimation behavior against unknown-feed muting, frame timing against sample accumulation, probe acceptance against the actual decoder, and fixture claims against included files. Repository source was not edited; no test result is claimed from this read-only pass.
