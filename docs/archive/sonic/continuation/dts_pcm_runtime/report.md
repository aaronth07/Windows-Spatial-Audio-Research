# DTS to PCM runtime continuation

Both the spatial-float and ordinary packed-PCM routes now feed sixteen-column float transport through allocation-free frame adapters. The spatial route supplies ten speaker signals plus six silent columns. Ordinary PCM supplies twelve populated columns plus four silent columns, with two proportional surround pairs representing the same two original surround signals. The ordinary route decoded the complete fixture without a metadata endpoint. Later compressed-header inspection identifies this fixture as UHD-framed and channel-based; original moving XYZ is not part of its signaled representation. Playback, device latency, other DTS object formats and arbitrary speaker geometry remain separate integration requirements.

All work ran in isolated processes without audio output/capture streams or endpoint, provider, service, registry, driver, or installed binary changes. The decoder SHA-256 remained `0fb48a12aef354016992e5fc2a34ea7ef4852711a5f48a66bdff07661285c4ca`. Shared REA analysis was exported and its target closed before completion. Original sources and the original decoder were not edited.

## Complete ordinary PCM12 transport

`packed_pcm12.h` converts signed little-endian packed 24-bit input to planar float and publishes it into `Pcm12Ring`, the twelve-input specialization of the same SPSC ring. The conversion has a preallocated 49,152-byte planar workspace and no per-packet allocation. Input must contain exactly `frames × 12 × 3` bytes with 1–1,024 frames. The first twelve output columns preserve the observed decoder order; columns 12–15 are zero. `pcm12_transport_contract.json` declares signal identity and the unassigned physical coordinates explicitly. Both twelve-column surround pairs are proportional to the same two native surround signals, so this remains ten independent decoded speaker signals.

The final 480-frame read contains 224 valid frames plus 256 zeros. ## Frame adapter and timing

`pcm_ring.h` implements one producer and one consumer with lock-free 64-bit indices. Construction allocates a 4,096-frame, sixteen-column buffer (262,144 PCM bytes) and sparse matrix routes. Push and Pop allocate no memory. Push checks input pointers, finite samples, expected absolute sample index, EOF and free space before publishing. Pop copies 480 or 128 frames and zero-fills any shortage; its return value identifies valid source frames. Starvation inserts silence without advancing the source index. The caller must count this separately and decide whether to delay, resynchronize, or drop at an explicit discontinuity. Reset requires both threads stopped and returns the number of discarded queued frames.

The native order is Center, FrontLeft, FrontRight, SurroundLeft, SurroundRight, LFE, TopFrontLeft, TopFrontRight, TopBackLeft, TopBackRight. The default sixteen-column output is FrontLeft, FrontRight, Center, LFE, SurroundLeft, SurroundRight, TopFrontLeft, TopFrontRight, TopBackLeft, TopBackRight, then six unused silent columns. See `transport_contract.json`. A custom sixteen-output mixing matrix was also tested; derived mixtures are not independent decoded objects. Speaker geometry and a PCM+XYZ panner are not part of the matrix or ring.

The initial negotiation/ten-input measurement run is `run_20261016T190447182Z/`, with per-case logs, raw packed PCM, provenance and `ring.json`. Those native checks decoded only 64 packets (65,536 frames, 1.36533 seconds), enough to include nonzero content. Full adapter checks used all 2,883,584 retained frames per channel (60.0746667 seconds) and compared every output float bit-for-bit with the expected matrix result. The later regression run after ring generalization is `run_20261016T191701680Z/`; complete native PCM12 runs are listed above.
