No rendering-time file I/O or DllMain initialization was added.

`preparation_gate_ready/result.json` closes the separate early-entry safety defect. Each of two workers observes eight initial and 200 preparation-window E_UNEXPECTED factory results, then waits for readiness and a shared worker barrier before 32 successful Create/Release operations each. The pre-initialization helper returns E_UNEXPECTED safely; actual helper address ownership matches the pinned System32 export. All 64 successful factory references are released, repeated initialization succeeds, and no DSP or successful unknown-ABI helper call occurs. The observed preparation window contains only failures; actual audiodg retry or failure handling is unproven. See factory_initialization_review.md for exact source/result limits.

## Remaining system prerequisites

1. **Endpoint identity and host sharing.** Current read-only observations expose one audiodg PID with hidden path/command line; sampled existing logs do not link selected virtual endpoint to it. One process does not imply one endpoint. Bootstrap can log the supplied endpoint GUID and PID, but the private CPU factory has no established per-engine endpoint identity. Basename resolution and current factory state are process-wide. No synthetic owned-host test resolves real host sharing.
2. **Configuration and restoration.** A complete current selected virtual endpoint effect-chain/COM/property snapshot, exact SFX/MFX placement preserving existing effects, and a tested restoration operation are still needed. Private settings work in memory; actual Windows property delivery, staged file read access and explicit log-path write access remain unverified. File-access failure must be distinguished from module-admission failure.
3. **Resident module lifetime.** Restoring endpoint properties does not unload a selected CPU module. bootstrap_apo.cpp:134 releases its own retained module only when no bootstrap instances remain; line139 prevents unloading while configured. regfree_factory.cpp:165 always returns S_FALSE from DllCanUnloadNow and retains its helper-module reference. A proven host-lifetime transition or selective native pass-through is needed. Retiring an unisolated host could affect other endpoints.
4. **Actual admission and first load.** Existing unsigned Equalizer APO and DisableProtectedAudioDG=1 observations reduce an assumed barrier but do not prove admission of this DLL or actual host mitigations. A loaded bootstrap, selected factory and custom rendered stream require separate positive markers. Recent WSSAPI input/clock trials do not identify Sonic as the selected renderer. Early E_UNEXPECTED is now safe in the tested entry points; whether the host retries or abandons creation remains unknown.
5. **Current execution access.** host_admission_access.json (2026-10-16T19:55:35.9808765Z) reports process_admin_token=false. Opening the existing selected virtual endpoint effects and machine COM class keys with write access is denied. This was an access probe only: no keys or values were created, changed or removed. It is an actual current-token access block, separate from authority and technical isolation.

The smallest next real-host experiment therefore remains inert admission with preload disabled, an exact endpoint-only placement and rollback artifact, suitable execution access, and bounded initialization logging. Custom preload should follow only after process scope, first-load behavior and restoration are resolved. No system action was performed by this review.
